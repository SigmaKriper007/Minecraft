# Minecraft Texture & Visual Design System

## 0. НАЗНАЧЕНИЕ SKILL

Этот skill определяет единые правила работы со всеми визуальными ресурсами Minecraft-мода.

Используй его при работе с:

* предметами;
* оружием;
* инструментами;
* бронёй;
* шлемами;
* мобами;
* entity textures;
* entity models;
* двухслойными и многослойными текстурами;
* блоками;
* рудой;
* декоративными блоками;
* сундуками;
* верстаками;
* механизмами;
* GUI;
* эффектами;
* частицами;
* текстурами интерфейса;
* icon/textures;
* 2D item models;
* 3D item models;
* UV-развёртками;
* PNG;
* pixel-art;
* ASCII/palette-based procedural textures.

Главная задача:

**Весь мод должен выглядеть как единая визуальная вселенная.**

Нельзя создавать каждый предмет независимо от остальных.

Новые текстуры должны соответствовать уже существующему художественному языку проекта.

---

# 1. ГЛАВНЫЙ ПРИНЦИП

Работай не как генератор случайных картинок.

Работай как:

**pixel artist + Minecraft resource artist + technical artist + Minecraft mod developer.**

Перед созданием любого нового визуального элемента:

1. Изучи существующий проект.
2. Найди похожие существующие ресурсы.
3. Определи их размер.
4. Определи используемую палитру.
5. Определи UV-layout.
6. Определи стиль shading.
7. Определи толщину контуров.
8. Определи существующие ModelPart.
9. Определи существующий Renderer.
10. Только после этого создавай новый ресурс.

Если в проекте уже существует похожий объект:

**используй его как визуальный эталон.**

Не создавай новый стиль без необходимости.

---

# 2. ВИЗУАЛЬНАЯ ЦЕЛОСТНОСТЬ

Все ресурсы должны выглядеть так, будто их создал один художник.

Например:

```text
Great Helm
     ↓
Chest Armor
     ↓
Gauntlets
     ↓
Leg Armor
     ↓
Katana
     ↓
Blocks
     ↓
Items
```

Все они должны иметь общий:

* уровень детализации;
* pixel density;
* контраст;
* способ освещения;
* толщину контура;
* цветовую логику;
* форму бликов;
* форму теней;
* материал;
* визуальный язык.

Если Great Helm является главным визуальным эталоном брони:

**вся броня должна выглядеть как комплект, изготовленный тем же кузнецом.**

---

# 3. PIXEL ART

Основной стиль проекта:

**Minecraft pixel art / low-resolution game texture.**

Не использовать:

* anti-aliasing;
* blur;
* мягкие градиенты;
* фотографические детали;
* реалистичные материалы;
* subpixel details;
* размытие;
* сглаживание;
* случайный шум;
* высокочастотную детализацию.

Каждый пиксель должен иметь смысл.

Предпочтительно использовать:

```text
1 пиксель = 1 визуальное решение
```

а не пытаться компенсировать плохой силуэт большим количеством цветов.

---

# 4. РАЗМЕР ТЕКСТУРЫ

Всегда сначала определить требуемый размер.

Типичные размеры:

```text
16×16
32×32
64×64
128×128
256×256
```

Для маленьких предметов:

```text
16×16
```

Для сложных предметов:

```text
16×16 или 32×32
```

Для humanoid/entity skin:

```text
64×64
```

Для сложных entity:

```text
64×64 или 128×128
```

Не увеличивай разрешение просто ради детализации.

Если объект должен выглядеть как 16×16 Minecraft item, сохраняй 16×16.

---

# 5. ПРОЗРАЧНОСТЬ

Для PNG-текстур:

```text
transparent = отсутствие пикселя
```

Не заменяй прозрачность:

```text
RGB(0,0,0)
```

настоящим прозрачным alpha.

Не создавай фон вокруг предмета.

Для item texture:

```text
████
████
 ███
  ██
```

всё остальное должно быть alpha=0.

---

# 6. КОНТУР

Для небольших предметов желательно использовать контур.

Контур:

* обычно 1 пиксель;
* тёмнее основной поверхности;
* не обязательно чисто чёрный;
* должен соответствовать материалу.

Например:

```text
      highlight
         ↓
     PPPPP
    PAAAAAP
   dAAAAAAAd
   dAAAAAAAd
    dAAAAAd
     dddddd
```

Контур должен помогать читаемости силуэта.

Не обводи каждый пиксель бессмысленно.

---

# 7. ОСВЕЩЕНИЕ

По умолчанию использовать единое направление света:

**сверху-слева.**

То есть:

```text
свет
 ↘
  объект
     ↘
      тень
```

Светлые грани:

```text
P
f
```

Средние:

```text
A
B
G
```

Тёмные:

```text
d
S
e
```

Не менять направление света между текстурами без причины.

---

# 8. МАТЕРИАЛЫ

Каждый материал должен иметь собственную систему оттенков.

Например:

### Металл

```text
dark metal
mid metal
light metal
highlight
```

### Камень

```text
dark stone
stone
light stone
noise
```

### Кожа

```text
dark leather
leather
light leather
highlight
```

### Кристалл

```text
dark crystal
main crystal
bright crystal
energy highlight
white core
```

Не используй одну и ту же схему shading для всех материалов.

Металл должен выглядеть иначе, чем камень.

---

# 9. ПАЛИТРА

Если проект уже имеет палитру:

**никогда не добавляй новые цвета без необходимости.**

Используй существующую палитру.

Для процедурного pixel art:

```text
character → RGB color
```

Каждый символ должен соответствовать одному цвету.

Например:

```text
d = dark purple
A = purple
P = light purple
f = pale purple

c = dark cyan
C = cyan
W = white

S = dark metal
e = dark gray

H = dark brown
M = brown

D = bright metal
```

Если в проекте уже существует `gen_textures.py`, сначала изучи его палитру.

Не создавай вторую несовместимую палитру.

---

# 10. PROCEDURAL ASCII TEXTURES

Если проект использует ASCII-сетки:

каждая строка = строка пикселей.

Например:

```text
................
......dd........
.....dAAd.......
....dAPAd.......
...dAPPAd.......
....dAAd........
.....dd.........
................
```

`.` означает прозрачность.

Требования:

* фиксированный размер;
* каждая строка одинаковой длины;
* только допустимые символы;
* никаких случайных символов;
* симметрия там, где она нужна;
* контролируемый силуэт.

Перед выдачей сетки обязательно проверь:

```text
height == required height
width каждого ряда == required width
```

---

# 11. НЕЛЬЗЯ ПОДМЕНЯТЬ PIXEL ART AI-GENERATED ART

Если задача требует процедурной текстуры:

НЕ используй:

* AI image generation;
* blurry image;
* anti-aliased PNG;
* photorealistic rendering.

Правильный pipeline:

```text
Design
 ↓
ASCII / pixel matrix
 ↓
palette mapping
 ↓
Python
 ↓
PNG
 ↓
Minecraft
```

Если используется генеративное изображение только как референс:

```text
AI image
 ↓
reference
 ↓
manual pixel reconstruction
 ↓
palette
 ↓
final texture
```

Финальная текстура должна соответствовать палитре проекта.

---

# 12. ПРЕДМЕТЫ

Для предметов:

1. Определи силуэт.
2. Определи направление.
3. Определи material.
4. Добавь dark outline.
5. Добавь основные цвета.
6. Добавь highlights.
7. Проверь читаемость на 100% размере.

Для оружия особенно важно:

* рукоять;
* гарда;
* лезвие;
* наконечник;
* направление оружия.

Например, катана:

```text
handle → guard → blade → tip
```

Не допускай перевёрнутой геометрии.

Если предмет неправильно расположен в руке:

**сначала исправляй transform/rotation, а не текстуру.**

---

# 13. ITEM MODELS

Перед изменением item model:

найди:

* item JSON;
* parent;
* texture;
* display transforms;
* custom renderer;
* существующую 3D-модель.

Для обычного предмета сначала использовать стандартный Minecraft item model.

Для сложного оружия можно использовать:

```text
custom 3D model
+
custom renderer
```

Но не создавай custom renderer без необходимости.

---

# 14. ПОЛОЖЕНИЕ ПРЕДМЕТОВ В РУКЕ

Для предметов, которые держит Entity:

проверяй:

* rotation;
* translation;
* scale;
* hand side;
* first person;
* third person.

Правильная логика:

```text
hand
 ↓
handle
 ↓
guard
 ↓
blade
 ↓
tip
```

Рукоять должна находиться в руке.

Не переворачивай текстуру, если проблема находится в transform.

---

# 15. ДВУХСЛОЙНЫЕ ТЕКСТУРЫ

Для humanoid entities использовать концепцию:

```text
INNER LAYER
+
OUTER LAYER
```

Например:

```text
Inner:
████████████

Outer:
 ▓▓▓▓▓▓▓▓▓▓
```

Outer Layer должен быть:

* отдельной геометрией;
* немного больше Inner Layer;
* привязан к той же части тела;
* использовать ту же UV-систему или корректно связанную с ней UV-развёртку;
* поддерживать прозрачность.

---

# 16. ENTITY SKINS

Для humanoid entities по умолчанию использовать Minecraft-compatible UV layout.

Типичный размер:

```text
64×64
```

Структура:

```text
Head
Body
Left Arm
Right Arm
Left Leg
Right Leg
```

Если используется outer layer:

```text
Head
 ├── Inner Head
 └── Outer Head

Body
 ├── Inner Body
 └── Outer Body

Left Arm
 ├── Inner Arm
 └── Outer Arm
```

и аналогично для остальных частей.

---

# 17. OUTER LAYER НЕ ДОЛЖЕН БЫТЬ ПРОСТО ТЕКСТУРОЙ

Outer Layer должен существовать как отдельная геометрия.

Неправильно:

```text
одна модель
+
нарисованная поверх текстура
```

Правильно:

```text
Inner Model
+
Outer Model
```

Outer Model немного больше Inner Model.

---

# 18. АНИМАЦИЯ OUTER LAYER

Outer Layer должен наследовать transform родительской части.

Например:

```text
Head
 ↓
Outer Helmet
```

```text
LeftArm
 ↓
Shoulder Armor
 ↓
Forearm Armor
 ↓
Gauntlet
```

При движении:

```text
Body rotates
 ↓
Chest Armor rotates

Arm rotates
 ↓
Armor rotates

Head rotates
 ↓
Helmet rotates
```

Никаких независимых неподвижных частей.

---

# 19. БРОНЯ

Броня должна восприниматься как набор отдельных пластин.

Не использовать один огромный гладкий mesh.

Пример:

```text
Helmet
Chest
Shoulders
Upper Arms
Elbows
Forearms
Gauntlets
Belt
Hip Plates
Thighs
Knees
Shins
Boots
```

Каждая часть должна иметь собственную форму.

---

# 20. БРОНЯ: ЕДИНЫЙ SET

Если один элемент брони уже существует и хорошо выглядит:

**он становится визуальным эталоном всего сета.**

Например:

```text
Great Helm
 ↓
REFERENCE

Chest
Shoulders
Arms
Legs
Boots
 ↓
adapt to Great Helm
```

Сохраняй:

* материал;
* цвет;
* толщину;
* декоративные полосы;
* форму краёв;
* заклёпки;
* highlights;
* shadows.

Все части должны выглядеть как один комплект.

---

# 21. БРОНЯ: MEDIEVAL PLATE STYLE

Если используется средневековый стиль:

используй:

* крупные металлические пластины;
* overlapping plates;
* rivets;
* reinforced edges;
* pauldrons;
* gauntlets;
* knee guards;
* greaves;
* sabatons;
* belts;
* central plates.

Не превращай броню в:

* sci-fi armor;
* tactical armor;
* modern armor;
* smooth exoskeleton.

---

# 22. БЛОКИ

Блоки должны учитывать все стороны.

Перед созданием texture определяй:

```text
top
bottom
north
south
east
west
```

Если блок имеет разные стороны:

не используй одну текстуру автоматически для всех.

Например:

```text
front
back
side
top
bottom
```

---

# 23. БЛОКИ С УЗОРАМИ

Для руды:

```text
stone base
+
ore veins
```

Жилы должны:

* вписываться в камень;
* не выглядеть как случайные RGB-пятна;
* использовать палитру проекта;
* иметь небольшое shading;
* сохранять читаемость при тайлинге.

---

# 24. TILEABLE TEXTURES

Если текстура используется как block tile:

левый край должен визуально соединяться с правым.

Верхний край должен соединяться с нижним.

Не создавай:

* очевидные швы;
* уникальный объект в центре;
* направление, которое выдаёт повторение.

Проверяй texture как минимум в сетке:

```text
2×2
```

---

# 25. БЛОКИ С АНИМАЦИЕЙ

Если блок имеет:

* огонь;
* энергию;
* свечение;
* вращение;
* активное состояние;

разделяй:

```text
base texture
+
active texture
```

Например:

```text
furnace_front
furnace_front_lit
```

Не меняй всю текстуру блока, если нужно изменить только состояние.

---

# 26. СВЕЧЕНИЕ

Для glowing elements:

используй:

```text
dark energy
main energy
bright energy
white hot core
```

Например:

```text
d → A → P → f → W
```

Яркость должна быть локальной.

Не делай весь объект одинаково ярким.

---

# 27. КРИСТАЛЛЫ

Кристаллы должны иметь:

* тёмную основу;
* основные грани;
* светлые грани;
* энергетическую жилу;
* hotspot.

Форма должна быть геометрической.

Не используй реалистичную фотографическую прозрачность.

---

# 28. МАТЕРИАЛЫ ДОЛЖНЫ ОТЛИЧАТЬСЯ

Металл:

```text
sharp highlights
```

Камень:

```text
rough shading
```

Кожа:

```text
soft pixel clusters
```

Кристалл:

```text
faceted highlights
```

Энергия:

```text
bright center
```

Дерево:

```text
directional grain
```

Не используй одну схему на всё.

---

# 29. ENTITY MODEL SCALE

Если модель должна быть больше:

разделяй:

```text
Visual Scale
+
Physical Dimensions
```

Visual Scale:

```text
Model × 2
```

Physical:

```text
EntityDimensions × 2
```

Не допускай:

```text
huge model
+
tiny hitbox
```

Проверяй:

* collision;
* eye height;
* attack range;
* navigation;
* pathfinding;
* bounding box.

---

# 30. ТЕКСТУРА И МОДЕЛЬ — РАЗНЫЕ ВЕЩИ

Не пытайся исправить проблему модели текстурой.

Если:

```text
катана перевёрнута
```

исправляй:

```text
rotation / translation
```

Если:

```text
броня пересекается с телом
```

исправляй:

```text
ModelPart geometry / scale
```

Если:

```text
цвет неправильный
```

исправляй:

```text
texture / palette
```

Если:

```text
UV неправильный
```

исправляй:

```text
UV mapping
```

---

# 31. РАБОТА С РЕФЕРЕНСАМИ

Если пользователь предоставляет изображение:

используй его как:

**design reference.**

Анализируй:

* силуэт;
* пропорции;
* материалы;
* цвет;
* форму;
* расположение деталей;
* визуальный язык.

Не копируй фотографические детали буквально.

Для Minecraft адаптируй объект под:

```text
blocky geometry
+
pixel art
+
limited resolution
```

---

# 32. ПРИОРИТЕТЫ ПРИ СОЗДАНИИ

Всегда соблюдай такой порядок:

```text
1. Silhouette
2. Shape
3. Proportions
4. Material
5. Major details
6. Shading
7. Highlights
8. Micro-details
```

Никогда не начинай с мелких деталей.

Если силуэт плохо читается, дополнительные пиксели проблему не решат.

---

# 33. СИЛУЭТ

На маленькой текстуре силуэт важнее детализации.

Проверь объект без внутренних деталей:

```text
████████
████████
 ██████
  ████
   ██
```

Если предмет всё ещё узнаваем — силуэт хороший.

---

# 34. СИММЕТРИЯ

Для:

* брони;
* шлемов;
* humanoid entities;
* механических объектов

сначала создавай симметричную основу.

После этого добавляй асимметричные детали.

Например:

```text
LEFT = RIGHT
```

затем:

```text
LEFT + unique detail
```

Не допускай случайной асимметрии.

---

# 35. ТЕХНИЧЕСКАЯ ПРОВЕРКА PNG

Перед использованием текстуры проверь:

* формат PNG;
* dimensions;
* alpha;
* отсутствие unintended background;
* допустимые цвета;
* отсутствие сглаживания;
* отсутствие лишних цветов;
* корректный путь;
* корректное имя;
* resource location.

Если используется палитровая система:

проверь, что каждый цвет присутствует в разрешённой палитре.

---

# 36. ПРОВЕРКА ASCII

Для ASCII texture:

```text
width = exact
height = exact
```

Например для 16×16:

```text
16 строк
+
16 символов в каждой строке
```

Запрещены:

* лишние пробелы;
* лишние символы;
* неправильная длина строки;
* неизвестные palette characters.

---

# 37. ПРОВЕРКА UV

Перед созданием сложной texture:

определи:

```text
texture resolution
+
face coordinates
+
UV coordinates
```

Не рисуй текстуру вслепую.

Если UV неизвестна:

сначала изучи ModelPart или существующую texture.

---

# 38. НЕ ЛОМАТЬ СУЩЕСТВУЮЩУЮ АРХИТЕКТУРУ

Перед изменениями:

```text
READ
 ↓
UNDERSTAND
 ↓
PLAN
 ↓
MODIFY
 ↓
BUILD
 ↓
TEST
```

Не:

```text
GUESS
 ↓
REWRITE EVERYTHING
```

Нельзя без необходимости:

* переименовывать registry IDs;
* менять package;
* удалять существующие модели;
* создавать дубликаты;
* менять loader;
* менять mappings;
* заменять renderer;
* удалять существующие textures.

---

# 39. ВЕРСИЯ MINECRAFT

API Minecraft сильно зависит от версии.

Поэтому перед написанием кода обязательно определить:

* Minecraft version;
* Fabric / NeoForge;
* loader version;
* mappings;
* Java version;
* используемые rendering APIs.

Не использовать код из другой версии без проверки.

Если API отличается:

**адаптируй решение к фактическому проекту.**

---

# 40. BUILD И VALIDATION

После изменения визуальной системы:

1. Запусти compile/build.
2. Исправь compile errors.
3. Проверь resource loading.
4. Запусти клиент.
5. Проверь texture.
6. Проверь model.
7. Проверь animation.
8. Проверь layering.
9. Проверь transparency.
10. Проверь scale.
11. Проверь UV.
12. Проверь отсутствие Z-fighting.

Не считай задачу законченной только потому, что код компилируется.

---

# 41. Z-FIGHTING

Если есть два близких слоя:

```text
Inner
Outer
```

Outer должен иметь небольшой геометрический offset.

Не допускай:

```text
████
████
```

когда обе поверхности находятся практически в одной плоскости.

Если возникает flickering:

проверь:

* scale;
* geometry;
* offset;
* render order.

---

# 42. PERFORMANCE

Не создавай чрезмерно сложную геометрию.

Предпочтительно:

```text
few ModelParts
+
smart geometry
+
good texture
```

а не:

```text
hundreds of unnecessary cubes
```

Особенно для сущностей, которые могут существовать в большом количестве.

# 49. ОСОБЫЙ ПРИНЦИП ДЛЯ ЭТОГО МОДА

Если пользователь показывает существующий объект и говорит:

**"сделай остальные в таком же стиле"**

не создавай новую интерпретацию.

Используй существующий объект как **STYLE ANCHOR**.

Извлеки из него:

```text
STYLE ANCHOR
├── silhouette language
├── material language
├── palette
├── contrast
├── highlight direction
├── outline style
├── detail density
├── geometry language
└── decorative motifs
```

После этого перенеси эти свойства на новые объекты.

Например:

```text
Great Helm
     ↓
STYLE ANCHOR
     ↓
Chest Armor
Shoulders
Gauntlets
Leg Armor
Boots
Weapons
Blocks
Items
```

Но не копируй форму шлема буквально.

Копируй **визуальный язык**.

---

# 50. ЗАПРЕТ НА СЛУЧАЙНЫЙ REDESIGN

Если пользователь просит:

> "сделай текстуру в таком же стиле"

это означает:

**сохранить существующую концепцию и визуальный язык.**

Не означает:

**придумать совершенно новый дизайн.**

Если существующий дизайн содержит:

* фиолетовые полосы;
* золотые элементы;
* серый металл;
* тёмный контур;

не заменяй их на:

* красный;
* зелёный;
* синий;
* другой металл

без прямого указания пользователя.

---

# 51. ФИНАЛЬНАЯ ЦЕЛЬ

Весь мод должен восприниматься как единый художественный проект.

Например:

```text
             WORLD
               │
       ┌───────┴───────┐
       │               │
    ENTITIES         BLOCKS
       │               │
    ARMOR            ORES
       │               │
    WEAPONS          MACHINES
       │               │
     ITEMS           TILES
       │               │
       └───────┬───────┘
               │
          SAME VISUAL
             LANGUAGE
```

Каждый новый ресурс должен выглядеть так, будто он всегда существовал в этом мире.

Главное правило:

**НЕ ПРОСТО СОЗДАВАЙ ТЕКСТУРЫ. СОЗДАВАЙ ЕДИНУЮ ВИЗУАЛЬНУЮ СИСТЕМУ МОДА.**
