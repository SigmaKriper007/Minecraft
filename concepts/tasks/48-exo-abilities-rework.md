# Задача 48: Переработка способностей EXO и слияние EXO-5/EXO-6

Дата: 2026-08-26. Статус: реализовано.

## Решение по лору
Старый EXO-5 Vengeance (перегрузка ядра, залп) **удалён из мода**. Слот EXO-5 занимает бывший
EXO-6 «Exo+» — он переименован в **EXO-5 Vengeance**. Это согласуется с лором
(`lore/lore.md`: EXO-5 — последний незавершённый проект Кодди, совершенное оружие конца войны):
тёмно-багровый гибрид всех линий теперь и есть этот финальный каркас.

## Новая общая система способностей (`ExosuitEntity`)

### Energy Shield (новый, единый для EXO-1/3/4)
- Активация: `activateEnergyShield(pilot)` — FLAG_SHIELD на 200 тик, пилот получает
  **Поглощение урона IV** (`MobEffects.ABSORPTION`, amplifier 3) на тот же срок («черепашья мощь»).
- Звук: `exo_shield`. Стоимость/КД задаются в каждом классе (слот остаётся прежним).
- **Анимация `energy_shield`** — новая, с нуля, в обоих файлах анимаций:
  руки выставлены вперёд (arm_joint X≈−82°, joint2 ≈−10°), торс −4°, голова +6°,
  удержание 1.2 с с микро-пульсацией ±3°, плавный возврат; длительность флага 30 тик.
- **VFX барьера** (единый зелёный язык энергии, по VFX-skill):
  - активация — convergence-вспышка зелёного;
  - пока щит активен — детерминированная сфера-оболочка (золотой угол + вращение от tickCount):
    ~70 % мелких HAPPY_VILLAGER (ярко-зелёный), редкий COMPOSTER (тёмно-зелёный внешний),
    каждые 8 тик один END_ROD у грудного ядра = белое hotspot-ядро (белое экономно);
  - **размер барьера привязан к модели**: радиус = max(1.1, bbWidth×1.05), высота от bbHeight —
    у каждого экзо свой масштаб автоматически.
- Урон при активном щите режется ×0.35 (уже было в `hurt`).

### Dash (новый, единый для EXO-2/3/4)
`performDash(pilot, distance=13)`:
- направление — взгляд пилота (прицел); коридор радиусом max(1.2, bbWidth×0.9);
- всё на пути **разрушается взрывом**: неразрушимое (bedrock, destroySpeed<0) и жидкости
  пропускаются; дропа нет (взрыв); FX EXPLOSION_EMITTER по ходу + GENERIC_EXPLODE;
- сущности в коридоре получают урон ×1.5 от атаки каркаса + отбрасывание вдоль рывка;
- движение — импульс v≈distance/11 (трение 0.91/тик ⇒ пролёт ≈13 блоков) через
  `applyImpulse` (сервер → пилотируемый клиент), плюс локальные частицы CLOUD.

### Heavy Laser (Cutting Laser EXO-2)
Слот 1 EXO-2 теперь стреляет настоящим `HeavyLaserBeamEntity` (как Heavy Laser Gun /
бывший Photon Lance): общий protected-хелпер `spawnDirectionalBeam(...)` перенесён из
Exo6Plus в базу, луч 75 блоков, обрезается коллизией, звук `exo_laser`.

## Технические изменения переименования
- Удалён `Exo5Vengeance.java` (старый). `Exo6Plus.java` → новый `Exo5Vengeance.java`
  (то же содержимое abilities, tier EXO_5).
- `ExoTier`: старые константы EXO_5+EXO_6 слиты в одну `EXO_5("EXO-5 Vengeance")`
  со статами бывшего EXO_6 (400 hp / 2500 energy / …).
- `ModEntities.EXO_5_VENGEANCE` — id `exo_5_vengeance`, sized(3.0, 9.0), класс Exo5Vengeance;
  запись EXO_6_PLUS удалена.
- Спавн-яйцо `exo_5_vengeance_spawn_egg` перекрашено в багрово-золотой (0x5A1420/0xE8941E),
  `exo_6_plus_spawn_egg` удалён (Java + модель + lang×5).
- Клиент: EXO_5_VENGEANCE → `ExoPlusRenderer`. Структуры: символ 'Z' теперь спавнит новую машину.
- Lang: убраны ключи guard_stance / fortify / launch / thrusters / mining_laser /
  exo_6_plus; energy_shield и dash остаются.

## Отклонённые подходы
- Телепорт-рывок серверным setPos: конфликтует с клиент-authoritative управлением
  транспортного Mob (резинка). Выбран проверенный путь applyImpulse.
- Рендер полупрозрачной сферы-щита геометрией: тяжело и ломает силуэт модели;
  частицы дешевле, читаются на дистанции и легко масштабируются по размеру каркаса.
