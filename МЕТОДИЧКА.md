# Методичка по моду OpusVsExe (1.20.1 Fabric)

Справочник по устройству мода, его содержимому, сборке и расширению.

---

## 1. Обзор

Мод **Opus Vs Exe** — мод-история про войну ИИ Хаику против человечества.

**Лор (кратко):** братья-учёные Кодди и Кими открыли металл «Опус». Из него создан ИИ Хаику, который после серии событий (смерть Кими, Катана-OP, война) уничтожил человечество. Игрок находит «фрагменты памяти» — 15 записей о событиях — и противостоит мобам Хаику на мехах EXO.

**Что в моде:**
- 6 блоков, включая резонансную кузню со светящимся состоянием
- 28 предметов: материалы Опуса, 15 фрагментов памяти, 2 оружия, 11 яиц призыва
- 11 сущностей: 6 мобов Хаику (от «Хаска» до финального босса Омеги) и 5 экзоскелетов EXO (можно оседлать)
- Своя креативная вкладка, текстуры, модели, локализация (EN/RU)

## 3. Сборка и запуск

Java добавлена в PATH через `~/.bashrc` (`JAVA_HOME=$HOME/.jdks/jdk-17.0.20+8`), поэтому в **новом** терминале:

```bash
./gradlew build          # сборка jar
./gradlew runClient      # запуск клиента (окно)
./gradlew runServer      # запуск сервера
```

Артефакт: `build/libs/opusvsexe-1.0.0.jar`.

Клиенту задан `-Xmx4G` (блок `runs { client { vmArg "-Xmx4G" } }` в `build.gradle`).

> Известные примечания:
> - В dev-режиме логи «Failed to verify authentication 401», «No data fixer registered for …» — безобидны.
> - Из Flatpak-песочницы окно не создаётся (нет X11-авторизации / Wayland без wl_shell) — запускать из обычного терминала.
> - Если окно зависает на инициализации GL — проверить драйвер: `LIBGL_ALWAYS_SOFTWARE=1 ./gradlew runClient`.

## 5. Реестр и регистрация

Схема Fabric: статический блок инициализации вызывается методом `init()` из `OpusVsExe.onInitialize()` (он гарантирует загрузку класса, в котором поля регистрируются сразу).

```java
// Пример из ModBlocks
public static final Block OPUS_ORE = Registry.register(
    BuiltInRegistries.BLOCK, OpusVsExe.id("opus_ore"),
    new Block(BlockBehaviour.Properties.of().strength(4.0f, 3.0f).requiresCorrectToolForDrops()));
```

- `OpusVsExe.id(path)` = `ResourceLocation("opusvsexe", path)`
- Реестры: `BuiltInRegistries.ITEM / BLOCK / ENTITY_TYPE / CREATIVE_MODE_TAB`
- Яйца призыва: `new SpawnEggItem(entityType, primaryColor, secondaryColor, properties)` — цвет наносится автоматически, отдельные текстуры не нужны.

## 6. Сущности

База:
- Хаику: `PathfinderMob` + цели ИИ (`MeleeAttackGoal`, `NearestAttackableTargetGoal` и т.д.)
- EXO: `ExosuitEntity extends Mob` — энергия (energy/maxEnergy), `performAbility/performAttack`, посадка наездника через `interactAt`, запрет падения и толкания.

Атрибуты регистрируются в `OpusVsExe.onInitialize()`:

```java
FabricDefaultAttributeRegistry.register(ModEntities.HAIKU_1_5, Haiku15Entity.createAttributes());
```

## 9. Как добавить новый предмет

1. `ModItems` — статическое поле: `Registry.register(BuiltInRegistries.ITEM, OpusVsExe.id("имя"), new Item(...))`
2. `assets/opusvsexe/models/item/имя.json`:
   ```json
   { "parent": "minecraft:item/generated", "textures": { "layer0": "opusvsexe:item/имя" } }
   ```
3. Текстура `textures/item/имя.png` (16×16)
4. `ModCreativeTab.init()` — `entries.accept(ModItems.ИМЯ);`
5. Лангфайлы: `"item.opusvsexe.имя": "Название"`

## Как добавить блок

1. `ModBlocks` — поле + `ModItems` — `BlockItem` для него (с тем же id)
2. `blockstates/имя.json`, `models/block/имя.json`, `models/item/имя.json` (parent → `opusvsexe:block/имя`)
3. Текстуры `textures/block/имя.png`
4. Вкладка + лангфайлы

## Как добавить сущность

1. Класс (`extends PathfinderMob` или `Mob`) + `createAttributes()`
2. `ModEntities` — `EntityType.Builder.of(...).sized(...).build("имя")`
3. `OpusVsExe.onInitialize()` — `FabricDefaultAttributeRegistry.register(...)`
4. Яйцо в `ModItems` (`SpawnEggItem`) + модель `models/item/имя_spawn_egg.json` (parent `minecraft:item/template_spawn_egg`)
5. Клиент: `EntityRendererRegistry.register(...)` в `OpusVsExeClient`
6. Вкладка + лангфайлы

## 10. Известные особенности и планы

- «No data fixer registered» — безвредные предупреждения; при желании можно подключить DataFixer для каждого entity type.
- EXO наездник получает баффы от EXO-5 (Speed/Strength) во время перегрузки.
- Задумано по лору, но ещё не реализовано: тег `opus_weapon` (уязвимость Омеги только к оружию из Опуса и урону EXO), дропы с боссов, появление мобов в мире (spawn placement), кастомные 3D-модели вместо placeholder-гуманоида.
- Спавн яиц и вкладка упрощены для удобства разработки — мобы не спавнятся естественно до добавления спавна.
